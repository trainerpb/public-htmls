Brute-Force Methodologies

The Strategy: Systematically enumerates all possible candidates and checks if they satisfy the problem. Guarantees a correct answer by leaving no stone unturned, but often scales terribly at $O(n^2)$, $O(2^n)$, or $O(n!)$.
Java: Linear Search
public int linearSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == target) return i;
    }
    return -1;
}

Greedy Paradigm

The Strategy: Makes the locally optimal choice ("taking the biggest bite") without looking back. Fast $O(n \log n)$, but fails if the problem lacks the mathematical "Greedy Choice Property."
Java: Greedy Coin Change
public void greedyChange(int[] coins, int amount) {
    for (int coin : coins) {
        while (amount >= coin) {
            amount -= coin;
            System.out.print(coin + " ");
        }
    }
}

Dynamic Programming (DP)

The Strategy: DP breaks problems into simpler, overlapping subproblems. By storing intermediate results in a matrix (Memoization/Tabulation), it avoids redundant recursion. This guarantees perfect global optimums and drops exponential complexities down to linear/polynomial bounds.
Use Case Breakdown: Climbing Stairs

What it says: Find distinct ways to climb $N$ steps by summing the ways to reach the previous two steps.

Java: DP 1D Array
public int climbStairs(int n) {
    int[] dp = new int[n + 1];
    dp[1] = 1; dp[2] = 2; 
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}

Use Case Breakdown: 0/1 Knapsack (Standard 2D Matrix)
Time Complexity: $O(n \times W)$
Calculates every cell in the 2D grid.
Space Complexity: $O(n \times W)$
Stores the entire matrix in RAM.

The Matrix Logic: Each cell dp[i][w] represents a universe where only the first i items exist, and the bag holds w kg. To calculate the current cell, we look at the row directly above us to compare the "Take It" vs "Leave It" branches.

Java: 2D Matrix Approach
public int knapsack2D(int W, int[] wt, int[] val, int n) {
    int[][] dp = new int[n + 1][W + 1];
    for (int i = 1; i <= n; i++) {
        for (int w = 1; w <= W; w++) {
            if (wt[i - 1] <= w) {
                // max( Leave It, Take It )
                dp[i][w] = Math.max(
                    dp[i - 1][w], 
                    val[i - 1] + dp[i - 1][w - wt[i - 1]]
                );
            } else {
                dp[i][w] = dp[i - 1][w]; // Forced Leave
            }
        }
    }
    return dp[n][W];
}

Use Case Breakdown: 0/1 Knapsack (1D Space Optimization)
Time Complexity: $O(n \times W)$
Still loops through all items and weights.
Space Complexity: $O(W)$
Drops the 'n' dimension! Massive RAM savings.

The Optimization Secret: In the 2D code, dp[i][w] only ever relies on values from dp[i - 1] (the previous row). We don't need the whole matrix! We can just use a single 1D array of size W + 1.

The Trap (Traversing Backwards): If we loop forwards (left to right), we might overwrite a small weight index, and then use that *new* value to calculate a larger weight index in the same row. This means we'd accidentally put the same item in the bag twice! By traversing Backwards (from W down to the item's weight), we guarantee that any lookup to dp[w - wt[i]] accesses the untampered value from the previous item's loop.

Java: 1D Space Optimized Approach
public int knapsack1D(int W, int[] wt, int[] val, int n) {
    int[] dp = new int[W + 1];
    
    // Iterate through items
    for (int i = 0; i < n; i++) {
        // TRAP: MUST traverse Backwards (W down to wt)
        for (int w = W; w >= wt[i]; w--) {
            // dp[w] acts as 'Leave It' (old value)
            // val[i] + dp[w - wt[i]] acts as 'Take It'
            dp[w] = Math.max(dp[w], val[i] + dp[w - wt[i]]);
        }
    }
    return dp[W];
}
